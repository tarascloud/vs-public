# MemPalace Knowledge Graph

**Status:** canonical reference
**Last updated:** 2026-04-11 (MP-IMPROVE-20260411-12)

## TL;DR

There is **exactly one** knowledge graph in MemPalace:

```
/opt/docker/mempalace/palace/knowledge_graph.sqlite3
```

It is a SQLite database owned and managed by the upstream `mempalace` package
(`mempalace.knowledge_graph.KnowledgeGraph`). It is mounted by `mcp_server.py`
at runtime and stores temporal entity-relationship facts with time-filtered
queries and fact invalidation.

The previously existing `palace/kg.json` file was a **dead artifact**. It was
generated by our local `init_palace.py` but never read by anything. It was
removed in MP-IMPROVE-20260411-12.

## Storage layers

| Concept | Storage | Written by | Read by |
|---|---|---|---|
| Drawers (verbatim files) | `palace/drawers/<wing>/<room>/*.md` | ingesters | scrubber, backup |
| Embeddings + sentinels | `palace/chroma.sqlite3` | ingesters, `init_palace.py` | search, audit |
| Wings/rooms directory layout | `palace/wings/<wing>/<room>/README.md` | `init_palace.py` | humans, audit |
| Knowledge graph (entities + facts) | `palace/knowledge_graph.sqlite3` | upstream `mempalace.knowledge_graph` via MCP | MCP server (`mcp_server.py`) |
| ~~`kg.json` manifest~~ | ~~`palace/kg.json`~~ | ~~`init_palace.py` (removed)~~ | **nothing — dead file** |

## Why two files looked like the KG

Until 2026-04-11 the palace directory contained both:

- `knowledge_graph.sqlite3` — the real temporal entity-relationship graph from
  upstream `mempalace==3.1.0`. Schema lives in
  `mempalace/knowledge_graph.py` inside the installed package.
- `kg.json` — a manifest written by our `init_palace.py` (function
  `write_kg_manifest`). It mirrored the `WINGS`/`HALLS` taxonomy into JSON.

There is no ADR or code that required `kg.json`. Exhaustive grep across both
the upstream package and `services/mempalace/` showed zero readers:

```
$ grep -rn 'kg\.json\|kg_json' /usr/local/lib/python3.12/site-packages/mempalace/
(no output)

$ grep -rn 'kg\.json\|kg_json' services/mempalace/
init_palace.py: write_kg_manifest / kg_file / etc.   # writer only
docs/ : references to file path                      # stale docs only
```

`kg.json` was therefore purely a side effect of `init_palace.py` — a leftover
from an earlier design that was superseded once the upstream
`knowledge_graph.sqlite3` KG shipped.

## What changed in MP-IMPROVE-20260411-12

1. Removed `write_kg_manifest()` from `mempalace/init_palace.py`.
2. Removed the call to it in `main()`.
3. Dropped the `import json` previously used only by that function.
4. Added this document plus an inline comment in `init_palace.py` pointing to it.
5. The live file `/opt/docker/mempalace/palace/kg.json` can be deleted during
   the next palace maintenance window — it is safe to remove and will not be
   regenerated by any subsequent run of `init_palace.py`. No ingester, search
   path, audit tool, or MCP handler ever read it.

## If you are writing new code

- **Do not** read or write `kg.json`. It does not exist anymore.
- **Do not** introduce a new KG manifest file. The single source of truth
  for wings/rooms is the `WINGS` dict in `init_palace.py`, mirrored into
  directory layout and Chroma sentinels.
- **Do not** bypass upstream `mempalace.knowledge_graph.KnowledgeGraph` — if
  you need to query entity/fact data, go through the MCP `knowledge_graph`
  tools, not the SQLite file directly.
- To surface wings/rooms programmatically, walk `palace/wings/` or query the
  Chroma sentinels by `type=wing` / `type=room`.
